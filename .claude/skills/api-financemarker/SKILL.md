# FinanceMarker.ru — REST API

Справочник по REST API сервиса [FinanceMarker](https://financemarker.ru). Справочник — **только описание эндпоинтов**: URL, параметры, поля JSON-ответа, edge cases. Вызовы выполняет Go-runtime проекта; никакого Python CLI и локального кеша в справочнике нет.

> **Прогрессивная загрузка.** Этот файл — каталог эндпоинтов + краткое описание. В `references/<endpoint>.md` для каждого эндпоинта лежит сигнатура (path/query-параметры) и поля JSON-ответа. **Читай reference только когда нужны детали** — для типового использования достаточно таблицы ниже.

---

## Авторизация

Все эндпоинты требуют API-токен из профиля <https://financemarker.ru/profile>.

- Токен передаётся query-параметром `api_token` (например `?api_token=$FINANCE_MARKER_TOKEN`).
- Тарифицируется не HTTP-запрос, а уникальная пара `(endpoint, тикер, точная query-строка include)`. Повтор того же ключа возвращает кешированный ответ и `day_limit` не двигает; стоимость новой пары растёт сублинейно с числом разделов в `include` (~1 за одиночный раздел, 2 за ~3 раздела, 3–5 за все 10 — зависит от объёма данных тикера). Модель — эмпирическая (сессия 2026-05-14), в публичной документации FM формулы и упоминаний кеша нет. Подробности — [`token_info`](references/token_info.md).

В примерах reference-файлов токен обозначен как `$FINANCE_MARKER_TOKEN` — подставляй фактическое значение из окружения.

---

## Базовый URL и формат

- Все пути — относительно `https://financemarker.ru/api/fm/v2/`.
- Ответ — JSON. Списочные эндпоинты возвращают массив объектов; одиночные (`token_info`, `idea`, `stocks/{exchange}:{code}`) — объект.

### Общие HTTP-коды ошибок

Один и тот же набор кодов возможен на любом эндпоинте — в reference-файлах дублировать не нужно.

| Код   | Когда                                                                                                                       |
| ----- | --------------------------------------------------------------------------------------------------------------------------- |
| `400` | Невалидные параметры запроса. Также `{"code":400,"message":"token_not_found"}` — если `api_token` не передан или невалиден. |
| `401` | Токен невалиден.                                                                                                            |
| `403` | Подписка просрочена либо исчерпан `day_limit`.                                                                              |
| `404` | Ресурс не найден (например, бумага / идея с таким ID).                                                                      |
| `422` | Невалидное значение query-параметра (например, `mode=last` у `dividends`).                                                  |
| `5xx` | Серверный сбой FM — повторить запрос.                                                                                       |

## Query-параметры пагинации

Все коллекционные эндпоинты (`stocks`, `dividends`, `ideas`, `experts`, `insider_transactions`, `disclosure`, `calendar`, `operation_metrics`) принимают одинаковый набор query-параметров — в reference-файлах он не дублируется:

| Параметр          | Тип          | Дефолт        | Описание                                       |
| ----------------- | ------------ | ------------- | ---------------------------------------------- |
| `limit`           | int          | сервер (≤100) | Размер страницы                                |
| `offset`          | int          | 0             | Сдвиг                                          |
| `sort_by`         | str          | сервер        | Поле сортировки                                |
| `sort_order`      | `asc`/`desc` | сервер        | Порядок                                        |
| `updated_in_days` | int          | —             | Только записи, обновлённые за последние N дней |

Эндпоинт-специфичные параметры (например `mode=upcoming` у `dividends`, `include=...` у `stocks/{exchange}:{code}`) описаны в соответствующем reference.

## Каталог эндпоинтов

Каталог ниже — **роутер**: по описанию решай, нужен ли эндпоинт, и только тогда открывай его reference.

### Базовые / справочники

#### `token_info`

- **Reference:** [token_info.md](references/token_info.md)
- **URL:** `GET /api/fm/v2/token_info`
- **Назначение:** `day_limit` (значение из ответа отстаёт от реального остатка из-за серверного кеша FM — точный остаток виден только в UI личного кабинета) и срок подписки. По эмпирическим замерам сам `token_info` фактически бесплатен / списывается крайне редко — можно дёргать свободно, но и полагаться на точное число нельзя.

#### `exchanges`

- **Reference:** [exchanges.md](references/exchanges.md)
- **URL:** `GET /api/fm/v2/exchanges`
- **Назначение:** список поддерживаемых бирж — нужен, чтобы проверить доступность биржи. **На текущей подписке — только MOEX**, поэтому при работе исключительно с MOEX эндпоинт не вызывают.

#### `operation_metrics`

- **Reference:** [operation_metrics.md](references/operation_metrics.md)
- **URL:** `GET /api/fm/v2/operation_metrics`
- **Назначение:** справочник операционных KPI (id, название, единица, множитель). Используется как словарь для расшифровки `operation_metric_id` из раздела `operations` карточки эмитента или чтобы узнать, какие KPI вообще доступны. Если значения метрик уже расшифрованы — эндпоинт не нужен.

### Эмитент

#### `stocks`

- **Reference:** [stocks.md](references/stocks.md)
- **URL:** `GET /api/fm/v2/stocks`
- **Назначение:** список компаний (`StockInfo[]`) с базовой карточкой (тикер, название, сектор, отрасль). Используй для полного перечня бумаг площадки или скрининга с клиентской фильтрацией по сектору/отрасли/стране — серверной фильтрации нет, только пагинация и сортировка. Для одной известной бумаги бери `stocks/{exchange}:{code}`.

#### `stocks/{exchange}:{code}`

- **Reference:** [stock.md](references/stock.md)
- **URL:** `GET /api/fm/v2/stocks/{exchange}:{code}?include=<sections>`
- **Назначение:** **главный эндпоинт по эмитенту** — полная карточка по конкретному тикеру: мультипликаторы, отчётность, дивиденды, инсайдеры, акционеры. Возвращает агрегированный объект `Stock` с разделами `info`, `summary`, `ratios`, `reports`, `dividends`, `ideas`, `insiderTransactions`, `operations`, `owners`, `shares`; набор разделов задаётся query-параметром `include`. Для выборки по нескольким эмитентам сразу — коллекционные эндпоинты ниже.

### Ленты по всему рынку

#### `dividends`

- **Reference:** [dividends.md](references/dividends.md)
- **URL:** `GET /api/fm/v2/dividends`
- **Назначение:** календарь дивидендов по всему рынку (ближайшие/прошедшие выплаты, стратегия дивидендного захвата). Поддерживает `mode=upcoming`. Для дивидендов одной бумаги бери раздел `dividends` карточки эмитента (`stocks/{exchange}:{code}`).

#### `ideas`

- **Reference:** [ideas.md](references/ideas.md)
- **URL:** `GET /api/fm/v2/ideas`
- **Назначение:** лента инвест-идей всех аналитиков (заголовок, target, потенциал, статус) — общая лента, фильтр по `updated_in_days`, сортировка по потенциалу. Для идей по одной бумаге — раздел `ideas` карточки эмитента, для деталей одной идеи — `ideas/{id}`.

#### `ideas/{id}`

- **Reference:** [idea.md](references/idea.md)
- **URL:** `GET /api/fm/v2/ideas/{id}`
- **Назначение:** полная карточка идеи по `id` с HTML-описанием тезисов автора. Бери, когда уже есть `id` идеи и нужны её детали. Если известен только тикер — иди в `ideas` или раздел `ideas` карточки эмитента.

#### `experts`

- **Reference:** [experts.md](references/experts.md)
- **URL:** `GET /api/fm/v2/experts`
- **Назначение:** рейтинг аналитиков как авторов (количество идей, % успешных, средняя доходность, средний срок) — для ранжирования авторов и поиска топ-аналитиков. Если интересуют сами идеи, а не их авторы, иди в `ideas` / `ideas/{id}`.

#### `insider_transactions`

- **Reference:** [insider_transactions.md](references/insider_transactions.md)
- **URL:** `GET /api/fm/v2/insider_transactions`
- **Назначение:** лента сделок инсайдеров **полным форматом** (~24 поля) для мониторинга покупок/продаж инсайдерами по всему рынку. Для инсайдеров одной бумаги в коротком формате — раздел `insiderTransactions` карточки эмитента (`stocks/{exchange}:{code}`).

#### `disclosure`

- **Reference:** [disclosure.md](references/disclosure.md)
- **URL:** `GET /api/fm/v2/disclosure`
- **Назначение:** лента **уже раскрытых** корпоративных событий (существенные факты, заседания СД и т.п.) — тайм-лайн раскрытий и мониторинг свежих фактов. Для будущих событий — `calendar`; первичные документы эмитента живут в e-disclosure.

#### `calendar`

- **Reference:** [calendar.md](references/calendar.md)
- **URL:** `GET /api/fm/v2/calendar`
- **Назначение:** календарь **предстоящих** корпоративных событий — план на ближайшие даты. Для уже произошедших событий — `disclosure`; только дивидендный календарь — `dividends`.

## Идентификация бумаги

Бумага в FM адресуется парой `<exchange>:<code>` (например `MOEX:SBER`, `MOEX:YDEX`, `MOEX:LKOH`, `MOEX:OZON`). Полный список бирж — `exchanges`, список тикеров — `stocks`.
