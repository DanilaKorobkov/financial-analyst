## 1. Синхронизация с main

Обновляем локальный `main` и подмёрживаем в текущую ветку:

```bash
git fetch origin main:main
git merge main
```

При конфликтах — разрешаем их вручную и завершаем merge-коммитом (без `rebase`, см. `.claude/rules/git.md`).

## 2. Проверки

Вызываем **task fmt checks** и устраняем все issues шаг за шагом.

## 3. Формируем название ветки

Смотрим все изменения сделанные в этой ветке с момента ее создания и чем она отличается от текущего main
`git diff main...HEAD`, анализируем и понимаем, что конкретно изменилось.
Переименовываем текущую ветку в соответствии с тем, что реально изменилось в diff
Если мы были на ветке `main` - создаем новую ветку.

Название передаем на валидацию пользователю в формате: Ветка: old-name → new-name

## 4. Commit & Push

Формируем название и описание коммита. Показать пользователю на подтверждение и ждать `ok`, после - commit & push.

Пример:

```
Файлы:
  - path/to/file1.py
  - path/to/file2.md

Название коммита: краткий заголовок

Описание коммита:
## Что сделано
- ...
- ...

## Зачем
...
```

## 5. Pull requests

### Если открытого pull request еще нет
Формируем и показываем пользователю на валидацию:

```
Название pull request: краткий заголовок

Описание pull request:
## Что сделано
- ...
- ...

## Зачем
...
```

После получения ок создаем pull request.

### Если открытого pull request уже есть

Актуализируем его название и описание по формату. Изменяем после явного ок от пользователя.

## Запреты скилла

- мердж PR (это делает человек)
- править файлы вне диффа без согласования
- создавать PR/коммит без `ok`
