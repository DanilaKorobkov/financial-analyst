# handoff

Запускается **только по явной команде** пользователя. Шаги по порядку, на падении — чиним и повторяем шаг. Git-правила (ветки, запреты на rebase/force/amend/--no-verify/`add -A`, формат сообщений) — в `.claude/rules/git.md`, не дублируем здесь.

## 1. Проверки

```bash
task fmt checks
```

Не подавлять линтеры (`// nolint` запрещён). Если ругается на код вне диффа или автофикс затронул посторонние файлы — спросить.

## 2. Дифф и ветка

`git status`, `git diff`. Если несколько независимых логических единиц — предложить разбить на коммиты. Если ветка `main` или имя не отражает суть — предложить `git switch -c feat-...` / `git branch -m feat-...`.

## 3. Подтверждение коммита (блокирующее)

Показать одним сообщением: список файлов, сообщение коммита, ветка (старое → новое если меняли). Ждать `ok`.

## 4. Коммит и push

```bash
git add <конкретные файлы>
git commit -m "<заголовок>" -m "<тело>"
git push -u origin <branch>
```

## 5. PR

Если открытый PR уже есть (`gh pr view --json url,state`) — показать ссылку, выйти.

Иначе собрать **на русском** название (отражает все коммиты ветки) и описание:

```
## Что сделано
- ...

## Зачем
...

```

Пустые секции опускаем. Показать, дождаться `ok`, создать: `gh pr create --base main --title ... --body ...`. Default-ветку при необходимости — `gh repo view --json defaultBranchRef`.

## Запреты скилла

- мердж PR (это делает человек)
- искусственное дробление коммитов
- править файлы вне диффа без согласования
- создавать PR/коммит без `ok`
