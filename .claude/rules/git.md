# Git

- Работаем только в feature-ветках вида `feat-<what-we-do>` (kebab-case). Не коммить в `master` напрямую.
- Перед стартом новой задачи: проверь текущую ветку. Если `master` или ветка от прошлой задачи — предложи создать `feat-<...>` и дождись подтверждения названия.
- Никогда не коммить и не пушь без явной просьбы.
- Триггер на предложение коммита: закончен milestone и собираемся начинать следующий. Тогда: предложи закоммитить текущее состояние перед стартом нового.
- Перед коммитом покажи:
  1. список файлов, которые пойдут в коммит (`git status` по делу),
  2. предложенное сообщение коммита.
  Дождись `ok` (или правок).
- После `ok`: `git add <конкретные файлы>` → `git commit` → `git push` в текущую feat-ветку (`-u` если впервые).
- Не используй `--no-verify`, `--amend`, `push --force` без явной просьбы.
- Никогда `git add -A` / `git add .`.
