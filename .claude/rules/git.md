# Git

## Проверки
- Нельзя пушить потенциально сломанный код - прежде чем пушить вызови `task checks` и добейся исправления ошибок.

## Типы
- `feat` `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `ci`

## Ветки

- Имя ветки: `<type>-<kebab-case>`. Никаких коммитов напримую в `main`.
- Расхождение с `main` разрешаем через `git merge origin/main`.

## Стейджинг и коммиты

- Стейджим только конкретные файлы. Никогда `git add -A` / `git add .`.
- Сообщение коммита — на русском, формат `<type>: <описание>`. 
- Заголовок ≤ 72 символа, описание — краткое страдательное причастие прошедшего времени (реализовано ...», «настроено ...»).

## Запрещено

- `git rebase` (включая интерактивный) — теряем линейную историю и ставим под риск чужие правки.
- `git push --force` / `--force-with-lease` — переписывает remote, ломает ревью.
- `git commit --amend` для уже запушенных коммитов.
- `git reset --hard` — данные пропадают безвозвратно; вместо него `git revert`, `git restore` или мердж-коммит.
- `git push --no-verify` — обходит хуки.

Все запреты снимаются **только** явной просьбой пользователя.
